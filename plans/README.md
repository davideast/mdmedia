## Dependency Notes

- **002 depends on 001**: `PlaybackEngine` loads tracks and reads duration/metadata from artifacts structured by `AudioLibrary`.
- **003 depends on 001 and 002**: `StudioStore` binds the storage catalog and the playback engine together with the Antigravity conversation watcher.
- **004 depends on 003**: The OpenTUI view layer is a purely declarative consumer of `StudioStore`; building the store first ensures the UI contains zero audio or disk logic.

## Findings Considered and Prethought

- **Scrubbing during live synthesis**: Resolved in 002/003 by separating `streaming` tracks (forward scrub clamped to buffered duration) from finalized `catalog` tracks.
- **`afplay -r` rate scaling calculation**: Resolved in 002 by multiplying elapsed wall-clock time by `playbackRate` before computing PCM byte offsets, preventing backward jumps on rate changes.
- **Filename sanitization and collisions**: Resolved in 001 by using deterministic prefixed slugs (`${sessionId.slice(0, 8)}_s${stepIndex}_${slug}`) clamped to 48 characters.
- **Headless core vs OpenTUI separation**: Resolved in 003/004 so that all storage, audio engine, and reactive store logic remain 100% headless TypeScript with zero React dependencies, isolating OpenTUI strictly to the presentation layer.
